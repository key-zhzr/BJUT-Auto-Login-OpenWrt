# 路由端流量存储（0.1.6-r30）

分钟明细按用户指定小时数保留，支持 7200 小时（300 天），不再有按估算行数计算的额外上限。小时、每日汇总也各自遵循设置中的保留时间。实际保存文件合计超过容量上限时，按时间清理最早记录，优先保留最新采样；保留时间和硬容量同时生效，不能保证任意设备数量、任意流量分布都能放进固定大小的闪存。

## 容量口径

容量单位为 MiB，设置中的 4 MB 对应 4,194,304 字节。计算以下实际写入闪存的文件长度之和：

| 文件 | 内容 |
| --- | --- |
| `usage-curves.tsv.dict.gz` | 分钟、小时、每日曲线，无损压缩 |
| `usage-samples.tsv.dict.gz` | 按天、账号、设备汇总 |
| `usage-curves.tsv.index` | 曲线时间索引 |
| `usage-switches.tsv` | 上游换号事件 |

不按 TSV 展开大小、预计每行字节数、各尺度固定份额或行数限制容量。RAM 中的追加日志、整理数组、压缩候选、旧代读取文件均不占此额度。闪存原子替换所需的临时副本另做文件系统剩余空间检查；空间不足时保留原文件和 RAM 中的新采样，记录错误并在之后重试。文件系统分配块和路由器其他组件不属于本插件数据额度。

`traffic-storage.json` 仅保存在 RAM，记录最近成功保存的 `flashBytes`、`limitBytes`、`retainedRows`、`trimmedRows`、`checkpointAt`。`trimmedRows` 仅统计真实容量触顶时清理的记录，不含到期记录。设置中的预计占用是范围估计；执行时始终以压缩结果为准。

## 采样和整理

- 每分钟采集计费系统的下载计数，继续保留真实开始、结束时间。按计费会话建立基线，换号、计数回退、断采的处理不变。
- 两次保存之间只向 RAM 中的小日志追加，不再在每个账号采样后对整个历史运行 AWK、排序和重写。
- 通常每 15 分钟、正常停止时整理一次。原生整理器以较低 CPU 优先级运行，合并相同桶及设备的记录，执行时间保留，再压缩并测量四个候选文件的总大小。
- 超出容量时依实际 gzip 大小迭代清理最早的完整时间戳，再测量；不将新记录裁掉来保留旧数据。
- 压缩候选通过完整解码和 gzip CRC 校验后，才替换闪存文件。原子发布新的 RAM 代目录同时切换压缩底本和空追加日志，避免切换时把一条记录重复计算。
- 读取者先打开文件描述符；下一次保存不会改变已打开的读取快照。当前代与上一代保留在 RAM，更早的代会被清理。

## 格式和按时间读取

支持原有 v1 字典 gzip 和 6/7 列日汇总、9/11 列曲线 TSV。升级先从已有 RAM 数据导入；重启从闪存压缩文件打开，不再将数月数据展开为完整 RAM TSV。新版本不会在卸载前自动把压缩历史展开到闪存。

曲线使用 v2 字典 gzip：设备、账号、接口元数据仍是 `D` 字典；`P` 行的时间为同字典/尺度上次时间的差，流量为同字典/尺度上次值的千分之一 MB 整数差；区间开始、结束为相对桶时间的偏移，秒数不变。整数差分是无损编码，没有降采样或降低计费精度。

每天一个独立 gzip member，每个 member 重置字典、时间与流量差分基线。索引记录该 member 的首尾时间和压缩偏移。图表按请求时间定位，包含首个部分桶和 RAM 新采样；查看过去某段时间不需要从第一条历史开始解压。旧 v1 无索引文件暂时顺序读取，下次保存会生成索引。

读取与候选整理有独立的 1 GiB 展开资源保护，用于拒绝损坏或异常输入；这个保护不从用户的闪存额度扣除，也不是原先“额度加 4 MiB”的小文件限制。

私有调试接口（仅供本地维护，不通过公共网页发布）：

```sh
# 得到当前 RAM 代目录
/usr/libexec/bjut-traffic-store path /var/run/bjut-autologin
# 流式导出完整逻辑记录，或按时间索引读取候选范围
/usr/libexec/bjut-traffic-store stream curves /var/run/bjut-autologin
/usr/libexec/bjut-traffic-store stream curves /var/run/bjut-autologin START END
```

范围读取会包含边界所在 gzip member 及追加日志，RPC 再按分辨率和精确范围筛选。不要直接修改代目录、manifest 或基线文件。

## 验证与升级

`openwrt/tests/test_traffic_store.py` 覆盖三条上游、每分钟一条、7200 小时共 1,296,000 条明细的压缩保存、重启、索引读取，以及真实容量触顶、旧格式、真实区间、追加切换、损坏输入保护。原生 RPC 与 shell 回退读取同一份压缩数据。

更新只替换 BJUT 本体和 LuCI 两个包。先离线模拟，检查交易计划；基础组件有任何变更、缺失依赖或 ABI 不匹配就停止，不使用 `--upgrade`。旧 r29 卸载脚本会展开历史，针对长历史升级应备份后禁用安装脚本，仅手动停止/启动 BJUT 服务，避免闪存被临时 TSV 占满。依赖和 Wi-Fi 版本必须保持不变。

旧版本已经丢弃的分钟记录不会凭空重建；原有小时、每日汇总和已有分钟记录继续保留。
