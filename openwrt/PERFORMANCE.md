# 路由端负载与进程生命周期（r33）

r33 修复实机上的重复出口重建：iproute2 会将协议号 `186` 显示为 `bgp`，原有 Shell 核对只认数字，误判已有规则缺失，并将自建连接路由混入前缀指纹。现在同时识别数字和名称；已有指纹通过原有加锁路径修复一次，之后由当前内核的只读核对复用。协议号、源地址限制和系统路由策略保持不变。

状态元数据发布器自行初始化 JSON 写入器，并在原子替换前验证结构；后台守护与 RPC 使用相同的完整快照。发布失败不会标记为完成，避免后台长期退回逐字段解析。

r32 补齐实机追踪发现的剩余高频路径：周期汇总直接复用原生状态读取器；没有手动任务时不创建操作更新子进程；已安装的出口规则通过只读 netlink 批量核对，源地址、设备、协议、优先级、表、网关或连接前缀不匹配时继续使用原有加锁修复路径。此核对读取当前内核，不使用过期路由缓存，不增加系统依赖。在线列表的解包与结构校验也合并为一次处理。

## 周期任务与分钟采样

r31 保留独立认证进程、PID/启动时间与出口锁，用 `prepared-context.json` 复用父任务已校验的非敏感配置、账号散列和凭据摘要。原生读取器检查文件权限、schema、配置与 UCI 待应用修改的内容指纹，缺失或不匹配时恢复完整加载。快照按数据读取，不执行其中的文本；明文密码和推送 token 不写入该快照，也不传给 jshn 的导出变量。需要凭据时核对配置版本并按需加载，提交认证前再次读取接口和网关。

每轮认证共享一次 `network.interface dump`。原生投影仍检查当前内核源地址，跳过 IPv6 tentative/deprecated/dadfailed 地址，分别保留 IPv4/IPv6 设备及路由信息；共享文件超过 5 秒或版本不匹配时不用。提交凭据前强制走实时读取路径。有线接口不再查询无线驱动；无线认证继续读取 SSID/BSSID。统计身份映射批量读取内核地址，并按物理设备去重。

状态、请求和门户响应使用批量字段投影；在线设备响应在一次原生处理内完成显示数据、MAC/IP 匹配、下载计数换算、稳定基线键、增量与真实区间。保持原有 SHA-256 标识、下载计费单位、计数高位、180 秒连续窗口，以及 v1/v2 字典 gzip、Flash 配额、7200 小时分钟保留和 15 分钟检查点。历史写入仍持有原有互斥，不改写成功请求的实际时间，也不延长认证或采样间隔。

监控中的 PID/启动时间读取改用 shell 内建读取，减少为存活检查启动 awk。计费 cookie 缓存的 owner、账号、出口和源地址签名不变，原有会话复用与账号回读校验继续生效。

探测按“服务 → 上游 → IPv4/IPv6 → 目标 → curl”逐层拥有子进程。每个直接子进程登记 PID 和内核启动时间，正常完成后回收，取消时先 TERM、限时等待，再按相同启动时间 KILL 和 wait。工作目录在回收后删除。

`bjut-runtime wait-probes` 使用单调时钟与原生 50 ms 等待，检查成功标记、工作目录、父任务及工作进程存活，最多等待配置的请求超时加 2 秒。它不会反复启动不支持小数的 BusyBox sleep。锁的短等待也使用原生休眠。

升级时仅清理旧版遗留探测：必须同时符合父进程为 PID 1、命令行属于本程序、标准输出指向已删除的私有 `work.*/probe4` 或 `probe6`。停止前后核对进程启动时间，不按名字批量结束进程。

## 页面查询

`status`、`dashboard`、`ports`、`accounts`、`traffic`、`billing_cached` 使用一个原生 JSON 读取器完成组装，避免每个账号、设备、字段分别启动 Shell、jsonfilter、散列和文本工具。它只读本地状态，不请求学校服务，不打开计费会话。

私有 `view-context.json` 仅保存显示所需的账号、上游、保留设置和凭据摘要，不保存明文密码。配置文件和 UCI 待应用文件的内容指纹用于失效；同一秒内的修改也会重新加载。指纹用于变更检测，不用于鉴权。元数据格式改变时需递增 schema。

状态、检测阶段、操作任务、网口字节数、账号套餐、计费结果及流量文件每次读取；数据年龄和超时也每次重算。因此没有延长界面刷新间隔，也不会缓存旧的操作进度。流量仍只使用计费下载计数，保留真实采样区间。

缓存缺失或不完整时走原有读取路径，并在配置稳定后原子发布元数据。轮询计费任务仍校验 ticket 和 owner，但不再为读取该任务重复加载全部 UCI。修改类操作继续完整加载配置和执行原有校验。

流量守护只在配置变化时重建内存配置；采样边界、换号唤醒、错误退避、基线、会话复用及压缩检查点保持原有规则。

## 验证

`python3 openwrt/tests/run_all.py` 包含原生视图与原有路径的对照、热查询不解析 UCI、配置与待应用修改失效、VIP 资格失效、ticket 所有权、故障退出、目录消失、连续停止及内存安全检查。主机测试需要 C 编译器、zlib 和 json-c 开发文件；Linux CI 安装 `zlib1g-dev libjson-c-dev`。

`test_runtime_batch.py` 另行对照新旧下载值、响应外层、MAC/IP 匹配、设备重复、基线键、计数回退、真实区间；覆盖惰性凭据读取、同秒配置变更、私有快照权限、当前内核源地址与过期网络投影。`BJUT_BATCH_DISABLE=1` 仅供离线对照，不是面向用户的配置项。

实机比较应同时记录整机 CPU、进程创建数和服务树 CPU。共享 rpcd 的成本不能全部归因本插件；页面活动、其他路由服务和采样阶段也需要记录。正常使用、连续查询及服务重启后均应检查没有新增孤儿探测，统计开关和历史保持不变。
