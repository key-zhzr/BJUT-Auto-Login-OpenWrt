# 路由端负载与进程生命周期（r29）

探测按“服务 → 上游 → IPv4/IPv6 → 目标 → curl”逐层拥有子进程。每个直接子进程登记 PID 和内核启动时间，正常完成后回收，取消时先 TERM、限时等待，再按相同启动时间 KILL 和 wait。工作目录在回收后删除。

`bjut-runtime wait-probes` 使用单调时钟与原生 50 ms 等待，检查成功标记、工作目录、父任务及工作进程存活，最多等待配置的请求超时加 2 秒。它不会反复启动不支持小数的 BusyBox sleep。锁的短等待也使用原生休眠。

升级时仅清理旧版遗留探测：必须同时符合父进程为 PID 1、命令行属于本程序、标准输出指向已删除的私有 `work.*/probe4` 或 `probe6`。停止前后核对进程启动时间，不按名字批量结束进程。

## 页面查询

`status`、`dashboard`、`ports`、`accounts`、`traffic`、`billing_cached` 使用一个原生 JSON 读取器完成组装，避免每个账号、设备、字段分别启动 Shell、jsonfilter、散列和文本工具。它只读本地状态，不请求学校服务，不打开计费会话。

私有 `view-context.json` 仅保存显示所需的账号、上游、保留设置和凭据摘要，不保存明文密码。配置文件和 UCI 待应用文件的内容指纹用于失效；同一秒内的修改也会重新加载。指纹用于变更检测，不用于鉴权。元数据格式改变时需递增 schema。

状态、检测阶段、操作任务、网口字节数、账号套餐、计费结果及流量文件每次读取；数据年龄和超时也每次重算。因此没有延长界面刷新间隔，也不会缓存旧的操作进度。流量仍只使用计费下载计数，保留真实采样区间。

缓存缺失或不完整时走原有读取路径，并在配置稳定后原子发布元数据。轮询计费任务仍校验 ticket 和 owner，但不再为读取该任务重复加载全部 UCI。修改类操作继续完整加载配置和执行原有校验。

流量守护只在配置变化时重建内存配置；采样边界、换号唤醒、错误退避、基线、会话复用及压缩检查点保持原有规则。

## 验证

`python3 openwrt/tests/run_all.py` 包含原生视图与原有路径的对照、热查询不解析 UCI、配置与待应用修改失效、VIP 资格失效、ticket 所有权、故障退出、目录消失、连续停止及内存安全检查。主机测试需要 C 编译器、zlib 和 json-c 开发文件；Linux CI 安装 `zlib1g-dev libjson-c-dev`。

实机比较应同时记录整机 CPU、进程创建数和服务树 CPU。共享 rpcd 的成本不能全部归因本插件；页面活动、其他路由服务和采样阶段也需要记录。正常使用、连续查询及服务重启后均应检查没有新增孤儿探测，统计开关和历史保持不变。
