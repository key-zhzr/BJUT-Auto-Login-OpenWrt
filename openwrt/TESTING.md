# OpenWrt 端测试说明

测试不使用真实账号，也不会访问校园网。`tests/mocks/curl.sh` 模拟三个门户，只接收程序通过标准输入交给 curl 的 URL；因此还可检查凭据是否意外出现在命令行参数中。

## 自动覆盖矩阵

| 类别 | 覆盖内容 |
|---|---|
| 编码 | 原 Rust 核心的 `dr1005`、`4.2.2`、Base64 固定向量；随机 Unicode、代理对、URL 百分号编码；IPv6 严格解析；非法 UTF-8/超长输入 |
| bjut-sushe | 正常 TLS、旧宿舍证书 SPKI 固定回退、SNI/Host/固定 IP、`@campus`、本地 IPv4、HTTP 明确启用边界 |
| bjut_wifi | HTTPS 固定网关、完整 Dr.COM 参数、特殊字符密码、多账号明确拒绝后轮换 |
| lgn | `loadUserInfo`、IPv6 发现、动态字段 XOR、主/备固定网关、缺少 IPv6 时仅提交已验证门户的 IPv4 认证；外部 IPv6 前缀不发送；模糊结果不重复提交 |
| 联网状态机 | 已联网快速路径、连续离线确认、登录后复核、指数退避、认证拒绝冷却、手动检查 |
| 失败语义 | 非校园 IP、SSID/BSSID 不匹配、协议/传输不匹配、无门户、门户未就绪、结果未知、超大响应、并发锁和陈旧锁恢复 |
| 隐私 | 密码、令牌不出现在进程参数和管理响应；账号完整显示，原始计费密码字段被移除 |
| 静态检查 | Dash 语法、LuCI JavaScript 编译、菜单/ACL JSON、ACL 无文件执行权限、捕获证书 SPKI 重算、C 编译警告、ASan/UBSan、UTF-8 与尾随空白 |
| 编译与发布 | 固件版本与 IPK/APK 对应、两个包完整性、架构校验、跨架构文件不互相覆盖、缺失矩阵/校验和不符/混用源码提交时拒绝发布 |

## 一键运行

开发机需提供 Python 3、可用的 C 编译器、Node.js、OpenSSL、Dash，以及支持 AddressSanitizer/UndefinedBehaviorSanitizer 的编译器运行库。

```sh
python3 openwrt/tests/run_all.py
```

也可只运行协议/状态机测试：

```sh
python3 -m unittest -v openwrt/tests/test_openwrt_port.py
```

## 未伪装为已完成的测试

以下项目必须在用户的实际设备/校园网络执行，当前离线环境无法诚实替代：

1. 将对应 SDK 生成的 IPK/APK 安装到匹配固件的设备；GitHub Actions 的交叉编译不能代替实机安装。
2. 在 `bjut-sushe`、`bjut_wifi` 和 `lgn` 三种真实网络分别执行一次 `manual`。
3. 验证目标固件 curl 的 TLS 后端支持 `--pinnedpubkey`；不支持时 bjut-sushe 旧证书路径应安全失败。
4. 测量目标路由器的实际 RSS、CPU 唤醒和 24 小时重连表现。

建议现场测试流程：

```sh
bjut-autologin check-config
/etc/init.d/bjut-autologin restart
/etc/init.d/bjut-autologin manual
bjut-autologin status
logread -e bjut-autologin
ps w | grep '[b]jut-autologin'
```

测试账号错误时请等待冷却，不要连续手动重试；真实网关若返回未知结构，应先保存脱敏响应结构再修改解析器，不能把未知结果当作成功。

## 0.1.6 新增验证

新增缺少 `cksum` 时四条数字编号上游的并行运行、路由清理、检测进度不覆盖结果、免密计费跳转、拒绝外部签名跳转与其他账号隔离验证。

覆盖多上游独立状态与账号、IPv4/IPv6 独立设备、已认证但外网目标失败、认证前可访问单个目标、未知响应保留登录、同一物理出口互斥、mwan3 规则保留与清理、没有主默认路由时的绑定出口表、设备与源地址不匹配、停用账号手动认证、已在线响应不轮换、计费会话复用、验证码续接与访问者隔离，以及账号同步失败不改原配置。

计费使用虚构页面和账号；凭据不会进入进程参数，原始 dashboard 密码字段不会进入管理响应。C 页面读取器进行地址/未定义行为检查，App 另验证固定证书的握手、错误证书拒绝和管理请求禁止跳转。

现场建议验证四条上游同时开启、单独关闭 IPv6、mwan3 将某条 WAN 判为离线，以及仅保留策略表默认路由的情况；逐条核对 `status` 中的设备、源地址、出口路由、认证会话和双栈结果。模拟与 SDK 构建不能替代这些现场验证。


## 修订 10

新增模拟用例覆盖按端口注销暂停/恢复、并行探测快速成功后终止慢目标、四类计费模块、访问者和账号隔离、命名操作与在线会话下线、响应歧义不重放、中断查询不持续等待、文件日志轮换及自有软链接边界。

App 原生测试另外覆盖网络特征匹配、设备标识错误时不发送密码或管理令牌，以及旧资料必须手动配对。界面验收包括三主题下拉菜单快速开关方向、高度动画反向及结束清理、移动端布局和日志滚动条。

可在开发机查看实际 LuCI 模块的模拟页面：

```sh
python3 -m http.server 1431 --bind 127.0.0.1 --directory openwrt
```

打开 `http://127.0.0.1:1431/tests/luci-regression.html`，点击“检查刷新与功能”。页面仅注入模拟 rpcd 数据，不访问真实路由器或校园网；覆盖控件聚焦持续刷新、单次请求失败恢复、注销切换、离页停止刷新及计费汇总。分别在桌面和 390px 窄屏验收。

真实 LuCI 主题、路由器登录耗时、多上游策略路由、真实计费变更和物理网络切换仍需现场测试，不以模拟通过替代。
